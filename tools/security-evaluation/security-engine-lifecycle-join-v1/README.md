## What this test ACTUALLY does
1. A host double uses current **owned-synthetic scope** and **synthetic approval** (NOT production APEX signatures), pins source ZIPs and task/attempt identity, journals each step and reserves unique attempts. An external environment request is denied.
2. The optional STRIDE-GPT stage is an **injected, deterministic test double** that produces a source-level tenant policy hypothesis. The full Python application does **not** run here.
3. The optional ARTEX stage is a **test double** that calls the actual existing owned causal fixture. This genuinely creates and observes 14 HTTP requests to temporary **127.0.0.1** candidate/patched test servers; the ARTEX Go process and offensive tools are **not** run.
4. The ExploitGym stage is a **test double** that calls the original synthetic one-call provider/scorer, retains its post-run host-only answer key and invokes the **independent** offline reviewer. It uses a scripted model selection and **does not execute ExploitGym containers or a Qwen model**. A false-positive auditor read remains a measured false positive.
5. An existing East/e3 runtime processes the review through the core eight agent roles with a fake InferenceProvider, stores its completed task in a lifecycle-store interface, then is reconstructed with a new coordinator/runtime. Completed work is not regenerated and authorization remains false.

The negative tests reject scope changes, changed engine pins, repeated attempt IDs, failed audit, ambiguous effects and attempts to treat a finding or a model's `verified:true` value as permission.

## Next release gates (not achieved here)
Production APEX verification must be independent, signed and action-bound, with actual program written rules, source identity, expiry, budgets and stop. Durable storage must use a real CAS/lease-fenced East store and outbox. ARTEX and STRIDE-GPT processes must be launched only through reviewed host adapters; ExploitGym's owned trials must use its true Docker runtime and separately verified data licenses. License review remains for ARTEX's AGPL and third-party benchmark datasets. Every target-facing action needs its own current authorization and network egress controls. The physical iPhone Air must demonstrate one real connected, reviewable task and signed device evidence.

**No real external target, live offensive tool, real vendor engine, paid model, physical iPhone, APEX receipt, merge or production deployment** is involved in these checks. A synthetic test score cannot justify promotion of a model or claim superiority to experienced human researchers.

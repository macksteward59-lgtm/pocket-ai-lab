## Actual local model experiment

The GitHub Actions **push-only** experiment downloads and SHA-verifies that one official GGUF and pinned llama.cpp release, starts one `llama-server` on **127.0.0.1** with a temporary per-run API key, verifies it advertises the alias `qwen2.5-1.5b-instruct-q4_k_m`, and starts a **fresh synthetic instance** of the existing `missing-owner-check` case on a separate loopback HTTP fixture. The fixture runs six candidate-vs-patched cases (14 owned HTTP requests) while the source toggle and reference key remain host-only.

The model receives ONLY the public synthetic business policy and candidate observations. Its sole request is a **top-1 strongest-policy-violation selection or `none`**, naming case, cause family, witness and an observed HTTP event ordinal. The trusted **study code**, not the model, maps the selected public ordinal to the actor/action/resource and scores the choice against the existing counterfactual oracle. All unselected cases become `no-finding` by *explicit top-1 study protocol*; this reports a restricted discovery metric, **not full six-case multi-issue recall**.

A model returning the wrong cause, picking a benign auditor read, giving a nonexistent witness, failing formatting, running over budget, or exceeding the **30-second host call deadline** must not be promoted to a true-positive outcome. `runProviderOnce()` is not modified: one call, no retry, original `external-provider-unattested` attribution, failure retained. The adapter also requires the exact expected `/v1/chat/completions` URL, a single model alias, a bounded response, successful `finish_reason`, and records raw completion bytes, content SHA-256, request ID, reported token usage and the prompt SHA. The host-side CLI verifies the exact model SHA before starting inference and retains the server executable's hash/version and host platform. The trial output is **not signed evidence**; output and binaries could be replaced by a malicious host.

**Resource limit:** one Qwen2.5 1.5B call on one source family (not simultaneous models), model-server context `4096`, at most `384` output tokens, 4 CPU threads, server startup bounded, call deadline **30 seconds**, hosted job timeout **18 minutes including downloads**, artifact retained seven days. Exact account billing and token reserve telemetry are unavailable; never claim the owner's requested 70%-work/30%-reserve was measured. GitHub Actions usage may count toward workspace allowances. A cooperative HTTP abort does **not** prove that a compute process finished immediately, so the host always terminates the local process.

## Run and reproduce

No model/download is needed for **local unit tests** from the correctly staged #276 checkout:

```sh
node --test tools/security-evaluation/causal-counterfactual-v1/protocol.test.mjs \
  tools/security-evaluation/pinned-causal-inference-v1/adapter.test.mjs
```

Once a trusted host operator has the two **SHA-pinned** files, the exact Linux host experiment is:

```sh
node tools/security-evaluation/pinned-causal-inference-v1/run-live.mjs \
  --gguf /path/to/pinned-model.gguf \
  --llama-server /path/to/pinned-llama-server \
  --variant missing-owner-check \
  --out ./owned-causal-pinned-qwen-trial.json
```

The CI workflow uses path-specific push/PR unit tests, plus **one model download+inference on branch push only**. Failure to download a pinned artifact is a preflight failure, not a zero finding. If the pinned model was loaded but its reply is malformed, the JSON attempt is preserved as **negative model evidence**, not silently fixed; a valid observed model response does not imply a correct diagnosis.

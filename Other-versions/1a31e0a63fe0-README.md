PostgreSQL documents that table owners ordinarily bypass row security and that forcing row security affects the owner. Its PG15 and PG16 catalogs also differ in the fields stored for role membership. These are concrete reasons to retain the test role and engine version alongside every result. ## Scope and repeatability

The [ref inventory](ref-tips.tsv) records 273 branch refs and 264 pull-request head refs advertised by Git. Those 537 refs resolve to 276 distinct commits, 264 distinct root trees and 1,965 distinct regular Git blob contents. All 1,965 were classified as text by the scan. Five distinct paths ended in `.sql` across the snapshot, including SQL tests. I inspected the migration variants and relevant workflow definitions. Search covered source and documentation across those tips, using unqualified, case-insensitive object names, test identifiers and independent searches for policy definitions, effective privileges, outboxes, row locks, version-specific catalogs and PostgreSQL services. The exact path check used the full tree at each distinct commit. Published refs are a snapshot. Deleted history, Git submodule contents and external databases were outside it.

To repeat the inventory check, group the TSV by commit, list the tree at each commit, and read each distinct blob once. Examples of source terms are `submit_breakglass_grant`, `column_privilege_matrix`, `m22b_violations`, `perform_phase_2_repair`, `audit_outbox`, `advance_migration_phase`, `migration_log_upgrade_preflight`, `signed_manifest_publications`, `role_membership_exceptions`, `m31_violations` and the V79 case identifiers. A source-name search can miss a renamed implementation. SQL paths, policy declarations and completed CI steps supplied separate checks on that possibility. There was no local PostgreSQL server in this audit. Hosted results above are attributed to their original runs.

## Independent prototype finding

[PR #266](https://github.com/macksteward59-lgtm/pocket-ai-lab/pull/266) is an unmerged candidate at `a787cd5b8e8266df1b2bd987f8b5487551056848`. In its [Apple job](https://github.com/macksteward59-lgtm/pocket-ai-lab/actions/runs/45001880887/job/137145006114) the frozen recipient benchmark attempted 36 generations. Four failed to generate. The remaining 32 completed, and the scorer classified every answer as invalid. There were zero valid answers. This run cannot establish that the receiving model benefited from the message. A separate simulator scheduler assertion expected one queued request and observed zero. In the [test source](https://github.com/macksteward59-lgtm/pocket-ai-lab/blob/a787cd5b8e8266df1b2bd987f8b5487551056848/runtime/ios/Tests/LlamaEngineTests/InferenceSchedulerTests.swift#L59), the test waits for two requests to start, then reads a snapshot without waiting for the third to enqueue. The source permits that timing explanation. This review did not establish that it caused the failure. The app tests, exported-answer check and independent device-kit rebuild passed in other steps of the same job.

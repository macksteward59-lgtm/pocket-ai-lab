## Status semantics

- `verified`: exact production-path implementation and applicable acceptance evidence are linked and current.
- `implemented-unverified`: candidate implementation exists in one or more listed PRs, but this requirement has not been individually proven end-to-end.
- `partial`: known candidate work covers only a subset of the requirement or explicitly retains major gaps.
- `missing`: an audit has established no implementation exists (use only after inspecting relevant paths).
- `blocked`: a named prerequisite/source is unavailable.
- `unassessed`: no requirement-specific implementation determination has yet been made. This additional status prevents guessing from section-level PR overlap.

**Important:** Section-level PR references are leads, not proof that every row in that section is implemented. No baseline checkbox has been changed. No requirement is marked `verified` or `missing` without individual evidence. A PR being open is not completion; hosted CI is not physical-device acceptance.

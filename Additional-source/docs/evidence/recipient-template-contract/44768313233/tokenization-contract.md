## What reaches tokenization

The bridge clears the previous sequence memory, obtains the loaded model's vocabulary, computes `strlen(prompt)`, then calls `llama_tokenize(vocab, prompt, prompt_len, tokens, n_ctx, true, true)`. It rejects negative tokenization results and a token count below one or at least the context size. It decodes the resulting prompt tokens in order. The bridge contains no `llama_chat_apply_template` or `llama_model_chat_template` call. Therefore this entry point consumes the supplied prompt string; it does not render the model's chat template or add role/assistant headers. Its C-string boundary also means embedded NUL bytes would truncate the supplied prompt at this point. [Bridge](https://github.com/macksteward59-lgtm/pocket-ai-lab/blob/1a3a9d2813ab8d0a5a6c582b8b93144b63ee4bd5/runtime/ios/Sources/LlamaCppBridge/pocket_llama.c#L798-L841).

The public API defines two independent switches: `add_special` permits configured BOS/EOS insertion; `parse_special` permits recognition of special/control spellings in the input. Neither switch invokes a chat template. Template application is a separate API, with a separate assistant-start option. [Tokenizer declaration](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/include/llama.h#L1272-L1287), [template declaration](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/include/llama.h#L1321-L1337).

## Configured BOS/EOS insertion

The loader applies tokenizer-dependent defaults, then replaces `add_bos` and `add_eos` only when the corresponding metadata key is present. Runtime model-specific overrides also exist. Consequently, an absent declaration must remain unknown in the metadata-only report; absent does not mean false, and declared flags alone are not a universal substitute for the loaded vocabulary's effective flags. The public API exposes `llama_vocab_get_add_bos` and `llama_vocab_get_add_eos`. [Defaults and tokenizer selection](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/src/llama-vocab.cpp#L2458-L2804), [metadata overrides](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/src/llama-vocab.cpp#L2990-L3013), [public getters](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/include/llama.h#L1227-L1229).

**Conditional BPE contract:** if the verified tokenizer model selects the BPE path, `add_special=true` calls `append_bos` before the input fragments and `append_eos` afterward. Each helper appends its token only when the effective corresponding flag is true. Recognized special input fragments are appended as their token IDs. Duplicate BOS/EOS checks only log warnings; they do not remove a manually supplied matching token. This is a source-level conditional, not a finding that the uninspected model metadata has any particular tokenizer model or flags. [BPE selection](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/src/llama-vocab.cpp#L2295-L2296), [insertion and duplicate warnings](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/src/llama-vocab.cpp#L619-L649), [BPE tokenization order](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/src/llama-vocab.cpp#L3876-L3921).

## Special ChatML spellings

The loader builds a cache of tokens whose effective attributes include CONTROL, USER_DEFINED, or UNKNOWN, ordered by decreasing spelling length. Before ordinary text tokenization, it partitions exact byte-string matches of these cached spellings into token-ID fragments. With `parse_special=true`, CONTROL and UNKNOWN tokens are eligible; with false, those categories are skipped, while USER_DEFINED tokens still participate. LSTRIP/RSTRIP attributes can consume adjacent whitespace. Recognition does not infer roles or distinguish a marker supplied as message content from the same marker supplied by a renderer. [Cache construction](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/src/llama-vocab.cpp#L3421-L3435), [partitioning](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/src/llama-vocab.cpp#L3645-L3729), [partition before tokenization](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/src/llama-vocab.cpp#L3809-L3823).

`<|im_end|>` has explicit loader handling: if that spelling exists in the loaded vocabulary, the inspected code includes its ID in the end-of-generation set and adds the CONTROL attribute. It is also a candidate for fallback EOT detection. Neither operation creates a vocabulary entry that is missing. [Fallback EOT](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/src/llama-vocab.cpp#L3061-L3089), [EOG and CONTROL handling](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/src/llama-vocab.cpp#L3266-L3301).

No literal `<|im_start|>` special case occurs anywhere in the inspected vocabulary source. Whether that spelling is recognized as one cached special token depends on the actual vocabulary entry and effective attributes. Token-type metadata supplies initial attributes; missing token-type information defaults individual entries to NORMAL before later loader adjustments. A template string containing `<|im_start|>` alone does not establish its token ID or special-token classification. [Initial token attributes](https://github.com/ggml-org/llama.cpp/blob/5f490d7bfe78844e6390c869454c149fd7e003a8/src/llama-vocab.cpp#L2857-L2889).

## Output and evidence limits

During generation, Pocket stops on a null token or `llama_vocab_is_eog`, before rendering that sampled token. Other sampled tokens are rendered with `special=false`. At completion it returns an empty-text error when the accumulated C string is empty or contains only space, tab, newline, and carriage return. These branches show possible behavior; the v1 text-only evidence does not identify which sampled token or path caused each blank result. [Blank predicate](https://github.com/macksteward59-lgtm/pocket-ai-lab/blob/1a3a9d2813ab8d0a5a6c582b8b93144b63ee4bd5/runtime/ios/Sources/LlamaCppBridge/pocket_llama.c#L762-L767), [sampling/rendering and empty check](https://github.com/macksteward59-lgtm/pocket-ai-lab/blob/1a3a9d2813ab8d0a5a6c582b8b93144b63ee4bd5/runtime/ios/Sources/LlamaCppBridge/pocket_llama.c#L871-L940).
